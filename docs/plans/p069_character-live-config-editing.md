# Character Live Config Editing — Plan

Makes the **Properties** (`_`-prefixed) values in the Character state window (p067) editable at runtime, so movement can be tuned (speed, jump, slopes, tumbling thresholds) without code edits and reloads. Tuned values can be exported as a `charData` override. This is a stub: scope, constraints and open questions only, to be expanded before implementation.

---

## 1. Goal (draft)

- Each Properties row in the p067 window gets an inline number input (click-to-edit or always-on, to be decided) that writes straight to `CharacterObject.data[key]`. That is the same live `characterData` object the controller reads every tick (built in `src/_engine/core/Character/DynamicCharacter.ts:369`, passed to `createCharacter` as `data` at `:866`).
- A "reset to default" action per row and for the whole group, using `DEFAULT_CHARACTER_DATA` (`DynamicCharacter.ts:192`, not exported yet) merged with the character's creation-time `charData` override.
- A "Copy as `charData` override" button that copies only the changed values as a TS/JSON snippet, ready to paste into e.g. `src/app/scene_thirdPersonGym.ts`'s `createDynamicCharacter({ charData: … })`.
- Optional: persist tuned values in localStorage per scene and character id, following the Camera/Light debug-override pattern (`src/_engine/core/PropertyLoader.ts`, `AEK_debugCams`/`AEK_debugLights`).

## 2. Constraints found so far

The 35 `_` values (after p066 Phase 1's config cleanup and Phase 3's `_turnToMoveDirection`) fall into three kinds:

| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Read live**, safe to edit directly            | `_maxVelocity`, `_jumpAmount`, `_jumpCooldown`, `_rotateSpeed`, `_runningMultiplier`, `_crouchingMultiplier`, `_inTheAirDiminisher`, `_accumulateVeloPerInterval`, `_isFallingThreshold`, `_minSlidingVelocity`, `_moveYOffset`, `_keepMovingAfterJumpThreshold`, `_tumbling*` (7), `_gettingUp*` (4), `_wallMicroPush`, `_wallNormalMaxY`, `_wallCastDistance`, `_slopeSlideSpeed`, `_turnToMoveDirection` (a boolean: a toggle, not a number input) | Write the value; it takes effect on the next tick. | **Derived at creation**                         | `_maxWalkableAngle` → `__maxWalkableAngleCos` (`DynamicCharacter.ts:376`)                                                                                                                                                                                                                                                                                                                                                                             | Recompute the derived `__` value on edit, through a small derived-value hook map.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Baked into colliders and probes at creation** | `_height`, `_radius`, `_crouchHeight`, `_skinThickness`, `_groundDetectorOffset`, `_groundDetectorRadius` (also the mesh `CapsuleGeometry`)                                                                                                                                                                                                                                                                                                           | They go through the derived dimensions, computed once at creation (`getCharacterDimensions`, `DynamicCharacter.ts:308-322`, called at `:373`). These size the colliders (`:714-852`), the wall cast and the floor ray. p066 Phase 4 turns that function into the body plan's `getDimensions`, which p066 §3.3 makes callable again from this plan's edit hook: that is the derived-value hook for these keys. Applying the result still needs the collider rebuild. So either keep them read-only, with a lock icon and tooltip, or "apply = recompute the dimensions and recreate the character's colliders" (needs a collider-rebuild path through the Physics API; the riskiest part). `_radius` is also read live for the floor ray's length (`:487`), so editing it without the rebuild would desync the ray from the colliders. |

p066 removed the unused keys (`_groundedRayMaxDistance`, `_tumblingAngDamping`, `_roundVelocitiesScalingFactor`), so there is no "declared but unused" kind any more. Every `CharacterData` field has a one-line JSDoc (`DynamicCharacter.ts:31-166`), a ready source for the rows' tooltips.

- **Undo.** Edits here are real data changes, so they should record undo actions with the debugger undo engine (`core/Debug/_dbg__UndoRedo.ts`, p060/p061, implemented: register an action handler, record on a finished change, coalesce slider drags). p061's inventory classed the tracker button as navigation-only (not recorded).

## 3. Open questions

- Should edits persist across reloads (LS), or stay session-only with copy-out being the persistence path?
- For collider-baked values: read-only for now, or tackle collider rebuild in this plan?
- Is `State` group editing (e.g. teleporting `position`, forcing `isTumbling`) in scope, or left to the edit window's existing position/rotation controls?
