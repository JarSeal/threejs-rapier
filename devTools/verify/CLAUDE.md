Notes for the verify commands (`devTools/verify/`: the scene runner and the baselines); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Verify commands

- `yarn verify:scenes`: It loads every scene of the generated data through the test bridge (see Debug system) in four configurations, `workerSab`, `workerMsg`, `mainThread` (debug env: errors, the determinism probe's hash, a 512 × 288 snapshot) and `prodTest` (errors only), and fails on a console or page error the config doesn't allow, a changed hash, a snapshot over the tolerance, or a load that ran in another physics configuration than it asked for. `--config quick` is `workerSab` alone. It starts its own dev server on 8092 unless `--url`. Baselines are local and per backend (`.cache/verify/scenes/<webgpu|webgl>/`: snapshots depend on the GPU and the driver): `--update` records every run without errors as good, so update on `main`, then run on the branch; the last run, with a `*.diff.png` per failed snapshot, is in `last-run.json` and `last-run/`. On WSL2 headless WebGPU can't render, so the page renders on WebGL2 (SwiftShader) without `--headed` (logged): WebGPU-only regressions need a `--headed` run on a real GPU. `--browser firefox` (p605 Phase 6; Playwright's Firefox, `npx playwright-core install firefox` once) is the cross-browser determinism run: the debug configurations only, always WebGL2, probe hashes only (no snapshots), compared with Chromium's baseline for the same scene, configuration and steps (the `webgl` file's entry, else `webgpu`'s, which it checks agree), never `--update`, its last run in `.cache/verify/scenes/firefox/`. A difference means the simulation depends on the JS engine: an issue file and an `unstableHash` with `browsers: ['firefox']` (`skip` and `allowedErrors` take `browsers` too). Run it after the Chromium run passes on the same commit, and before the PR of a change to simulation code (p610, p614). The full matrix takes about an hour on SwiftShader. `playwright-core` is a project devDependency, pinned to the run-aekasha-js skill's version, so they share its downloaded Chromium.
- `yarn verify:baselines [--update [--allow-docs-drop]] [--no-build] [--docs]` — diffs three committed files in `devTools/verify/baselines/` (`devTools/verify/baselines.ts`, `_DONE_p601` Phase 3): `bundle.json` (every file in `dist/assets/` by its name without the content hash, bytes and gzip, plus the main chunk's modules per group: a package, each engine folder, toolkit, app), `api.json` (every export of the documented API by module, with its kind, from the Hub's TypeDoc model, and each public entry's export names, read from its `index.ts`: the public surface, p606) and `docs.json` (documented / total exports and class and interface members per folder, the Hub's coverage rule, and each folder's undocumented ones by name, `SceneLoader#LoadSceneProps`, `ECS#ECSWorld.addSystem`). It exits 1 on a chunk whose gzip grew over 1 % or 2 kB (at least 100 B), a new chunk, an export added, removed, moved or of another kind, a name added to or removed from an entry, or a folder with more undocumented exports or members than recorded (the docs ratchet, p605: it names each new one with its file and line; a new folder starts at none); shrinking, better coverage and deleting documented code pass. `--update` writes the current state: commit it with the change that explains it. It refuses a grown undocumented count unless `--allow-docs-drop` is given too (say why in the commit; p608's moves rename folders, so it records them that way). It runs the build's bundle steps first (decoders, production gather, `vite build`, the dev gather again; no `tsc`, no Hub), 12-20 s; `--no-build` reuses `dist/` and `dist-stats/`. `--docs` checks (or records) `docs.json` alone, without the build, `api.json` or the progress log, in about 1 s (6 s when TypeDoc converts): the Stop hook runs it. Gzip sizes shift by a byte or two between builds with new content hashes, within the tolerance: don't commit such a `bundle.json` without a change that explains it.
