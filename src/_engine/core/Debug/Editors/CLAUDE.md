Notes for the editor views' own code (`src/_engine/core/Debug/Editors/`: the view camera, the editor drawer, the material editor); the views themselves are the root's Views section, and the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Views

- `createViewCamera({ viewId, defaultPose, near?, far?, store? })` (`core/Debug/Editors/_dbg__ViewCamera.ts`) is every editor's orbit camera: wire its `camera` and `rig` into `getCamera` / `getCameraRig`, and its `onEnter` / `onExit` / `mainUpdate` into the view's own. It keeps a pose per view and pose key (`setPoseKey(key)`: the editor's subject, `null` the view's own pose), saved when the controls' input ends and when a gizmo move ends (`onMoveEnd`), in `AEK_debugViewCams` or the view's own `store`. `clearViewCameraPoses(viewId)` backs a clear-LS button. It never touches the scene debug camera or `AEK_debugCams`.
- Material editor (`_DONE_p084`, `_DONE_p085`; `debug/MaterialEditor.ts` → `core/Debug/Editors/Material/`): the view `materialEditor`. It shows an editor copy of a `*.material.json` material (`__matEditor__<id>`, `isPersistent`, created on enter and on each selection, deleted on exit; the scene's own instance is never touched) on a private stage: a ball (points, lines or a sprite for those types), its own lights and a `RoomEnvironment` PMREM. The bottom selector picks the material (filter by id and name), and it loads only the textures that aren't registered yet. Its right drawer is `createEditorDrawer` (`Editors/_dbg__EditorDrawer.ts`), an instance any editor can create: ordinary `DebuggerTabDef`s mounted by a tab host of its own, setting `debugDrawerOpen` while its view is active and it is open. LocalStorage (`_dbg__MaterialEditorStore.ts`): the UI state in `AEK_debugMatEditorUI`, and one record per material, `AEK_debugMatEditorMat_<id>` (deviation-only: its `overrides`, in `MaterialOverridesSchema`'s `params` / `nodes` shape with JSON values; its editor `settings`, `_dbg__MaterialEditorSettings.ts`; its `camera` pose, fov included), always written read-merge-write through `patchMaterialRecord`.
  - Params tab: one catalogue for every material type (`_dbg__MaterialEditorParams.ts`): a param shows only when the copy has the key with the expected kind. TSL inputs set their uniform's `.value` (``mat.userData.uniforms[`${socket}_${input}`]``, no rebuild); textures and `staticDefines` are read-only. Node overrides are merged into the props before `createMaterial`, param overrides are set on the created copy, and an override equal to the asset's value is dropped (on an edit and on every load), so it follows the JSON again. Settings tab: the stage, the auto-rotation and the camera's fov (part of the pose, not a setting).
  - Undo: every binding records `materialEditor.setValue` (`perScene`, so the view's bucket; payload `{ materialId, section: 'params' | 'nodes' | 'settings' | 'camera', path, prev, next }`, coalesced per path). The handler applies live when the material is on the stage, else writes its record and selects it (the load builds from the record). The clear and reset buttons aren't recorded.
