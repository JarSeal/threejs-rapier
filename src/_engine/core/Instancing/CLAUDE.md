## Instanced mesh pools

`core/Instancing/InstancedMeshPool.ts` (`_DONE_p348` Phase 3; it was `toolkit/ecs/`, which keeps deprecated re-exports until the toolkit's next major): `createInstancedMeshPool` draws many instances with one `InstancedMesh`, each instance an entity with a `Transform` and `INSTANCED_MESH_SLOT` (`{ mesh, index }`), baked into the instance matrix by `instancedMeshPoolSyncSystem` (registered by the module, `APP_RENDER_SYNC`). Add `pool.mesh` to the scene yourself; its owning entity (`TAG_IS_MESH`) disposes it and releases the pool's registry refs. Freeing a slot (`despawn`, deleting the entity or removing the slot) is a swap-remove, so an instance's `index` can change: read it from the component. `createInstancedLodPool` has one mesh per level and moves instances between them through the LOD system's `registerLodTarget` seam; a LOD-culled instance is in no mesh (`index -1`), and a cross-fading one is in two (see LOD selection, `core/Lod/CLAUDE.md`). Every level mesh gets the union bounds of all placements at spawn.
