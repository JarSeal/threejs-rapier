Notes for authoring the Ækasha Hub (`hub/`: pages, layout, assets; the generator's are in `devTools/hub/CLAUDE.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Ækasha Hub

- Sources: `hub.config.ts` (title, description, `coverageIgnore` (see Features and homepage); the menu comes from the pages, the GitHub links from `package.json`'s repository), `_layout/shell.html` (the frame every page goes into: `{{name}}` placeholders filled by `shell.ts`) and `_layout/404.html` (the 404 page's body), `_assets/` (`scss/hub.scss` and its partials through `sass`; every `ts/*.ts` not starting with `_` is an entry bundled by Vite's `build()`; `icons/`, `fonts/`, `images/` copied as they are), `pages/` (one folder per URL), and `tsconfig.json` (`tsc -p hub`, DOM lib: the root `tsconfig.json` doesn't include `hub/`). The Stop hook runs on changes in `hub/` too and runs `tsc -p hub` after the root `tsc`.
- Pages: a folder under `hub/pages/` with an `index.html` is a page at its folder's path (`examples/physics/index.html` → `/hub/examples/physics/`), and needs its parent page. The `<head>` has `<title>` and `aek:` metas (`aek:menu` (label, default the title), `aek:order`, `aek:tags`, `aek:description`, `aek:icon` (top-level items), `aek:featured`, `aek:image` (see Scenes and examples), `aek:group`, `aek:covers` (see Features and homepage)); an unknown `aek:` name warns. The nav is rendered per page at build time from these alone (children by `aek:order`, then label). The `<body>` is the page's markup: every empty element with an `id` is a slot, filled by `<id>.md` in the same folder. An `.md` without a slot, or in a folder without an `index.html`, fails the build; a slot without its `.md` warns.
- Markdown (markdown-it, `markdown.ts`): heading ids (never one the page's markup has: a `quick-start` slot's "Quick start" heading gets `quick-start-2`) with a `#` anchor, and the "On this page" TOC (h2 and h3, from 3 headings, not on the homepage); `hub:` links (`[physics](hub:examples/physics#setup)`, also `href="hub:…"` / `src="hub:…"` in a page's markup) resolved to relative URLs and checked, a missing page or `#hash` failing the build with its file and line; `repo:` links (`[budgets](repo:docs/techniques/asset-optimization.md#budgets)`): a repo file, checked with its `#heading` (GitHub's slug, `readMarkdownHeadings` in `repoFiles.ts`) or `#L<line>`, linking GitHub at the build's commit in `public` and the editor in `dev`; `::: tip|note|warning|danger [title]` callouts, and `registerHubDirective(name, { open, close })` for new `::: name args` directives (`code-group`, `scene`, `cards`, `claude-md`, `dev-only`; nest with a longer marker on the outer one); `::: dev-only [title]` (p601) is content only the dev server's Hub shows: a directive with `devOnly: true` has its lines skipped before parsing in `public`, so none of it is in the built Hub (nor its TOC entries or search text) and `hub:build` doesn't check its links. The test and verify commands (the Quick start's "Check your changes") and the debug suite's test bridge are in such blocks; relative images, which must be inside the page's folder, copied to `_assets/images/pages/<page path>` (PNG and JPEG to WebP by sharp). A page's markup (not its Markdown) has `{{root}}`, `{{icon:name}}` (the SVG from `_assets/icons/` inlined, `currentColor`) and `{{asset:path}}` (a static asset's URL with its `?v=`); the shell also `{{link:path}}` (a checked page URL). An unknown icon, asset or page fails the build.
- Code blocks (p552, `code.ts`; the reference page is `hub/pages/documentation/code-blocks/`): shiki highlights at build time with two themes of our own (`codeThemes.ts`, every colour AA on the code background and its line tints), both in the HTML as CSS variables, so pages ship no highlighter. The fence meta (`title="…"`, `{3,5-7}`, `startLine=N`, `showLineNumbers` / `noLineNumbers`, `wrap`, `collapse`; an unknown word warns) and shiki's notation comments (`// [!code ++|--|highlight|focus|error|warning]`) add the rest; `` `fn()`{ts} `` highlights inline code. `::: code-group` turns its fences into tabs. An unknown language renders plain with a warning. `hub.ts` adds copy (the DOM's clean source: no numbers, notation or `--` lines), collapse and the tabs; without JS every line and block shows.
- Snippet includes (`snippets.ts`): `<<< path/from/repo/root.ts#region {meta}` (or the whole file, or `#L10-L24`) on a line of its own becomes an ordinary fence token, titled with its path. Regions are `#region name` / `#endregion name` in any comment style; a `.json` file has none. Included files go into the build's `files`, so in dev an edit to one rebuilds the Hub and reloads the pages that show it.
- Scenes and examples (p554, `devTools/hub/scenes.ts`, `cards.ts`): a Hub page shows the app's scenes, which `?startScene` opens (see Commands).
  - `::: scene <sceneId>` … `:::` is a panel: the scene's Hub image (webp at 800 and 1600 wide), the directive's content, then in `dev` "Open in debug" / "Open in prod test" buttons (`/?isDebug=true&startScene=<id>`), in `public` a note on running it locally (the public Hub runs no engine). The ids come from `src/_engine/generatedAppData.json` (`yarn build` gathers the development data again before `hub:build`): an unknown id fails the build in both modes, a missing image warns.
  - A scene's Hub image is `src/app/<sceneFile's folder>/<sceneId>.hub.png` (app scenes only; the same rule in `getHubImagePath`, `app/examples/_dbg__exampleHub.ts`, and `loadAppScenes`). It's written by the debug drawer's scene-scoped "Hub" tab, **Save Hub image**: a `takeSnapshotAsync` of what the canvas shows (active camera, PostFX, no viewports or debug helpers) at `CARD` 1600 × 1000 or `HERO` 1560 × 960, `encodePNG`, `writeDevFiles` (an unchanged PNG isn't written; without the dev files it's downloaded, with the path to put it at). A PNG isn't gathered, so a save doesn't reload the app, and the dev Hub watches the path (also before it exists), so it rebuilds. `registerExampleHubTabs()` (called from `src/index.ts` in the debug env) gives the tab, on enter, to every scene whose file is under `src/app/examples/` and to `OTHER_HUB_SCENES` (`lodShowcase`), so no example scene file holds debug code.
  - `aek:image` in a page's head (`scene:<sceneId>`, or an image path from the repo root) is checked into `HubPage.imageFile`, every page's before any page renders. `::: cards <page path>` (no content) renders a card per child page in the nav: its `aek:image` (else its `aek:icon`), nav label and `aek:description`, linking it, out of the search (`hubSearchSkip`). Filters after the path: `featured` (children with `aek:featured`; the list gets `hubCards_featured`) and `group=<name>` (children with that `aek:group`). With no image among its cards the list gets `hubCards_icons`: `.hubCards_featured.hubCards_icons` are the homepage's icon columns, laid out by container query on the cards' parent. A page's markup shows a scene's image with `<img data-aek-scene="<sceneId>" src="<fallback>" …>`: the build swaps in the webp (`srcset`, real size) and the class `hubSceneRender`, and keeps the fallback (with a warning) until the PNG is saved; the homepage hero is `exampleHubHero`'s.
  - The example scenes (`src/app/examples/<name>/`: `<id>.scene.json` named "Example: …", `<id>.ts`, its own camera, lights and asset ids, since `createGeometry` returns an id that's registered already with its old params) are ordinary app scenes in every build. Each page under `hub/pages/examples/` includes its scene's regions (and `AppECSRegistry.ts`'s / `AppECSPlugins.ts`'s for the ECS example): a scene file holds only the example. `exampleHud.ts` is their HUD line, removed by an all-scenes exit hook. `exampleHubHero` (`SPACE` sky box, toolkit asteroids, a bloom PostFX) has no page: it's the homepage hero's render. Changing an example changes its page: run `yarn hub:build`, and save its Hub image again when it looks different.
- Features and homepage (p555):
  - Feature pages: `hub/pages/features/<slug>/` (rendering, ecs, physics, scenes-and-assets, asset-optimization, sky-box, lod, spatial-index, viewports, debug-suite, characters, toolkit), each an `index.html` with an `intro` slot (the summary and the example's `::: scene` panel) and a `guide` slot (how it works, key APIs as `api:` links, related issues, "Read more"). `aek:group` puts each in one of the Features page's groups (Core, World, Performance, Tools, a `::: cards features group=<name>` each), and `aek:featured` marks the homepage's four (rendering, physics, ecs, debug-suite). The content is checked against the code like the CLAUDE.md files, and a feature change updates its page (see Workflow).
  - `aek:covers` (comma-separated) names the CLAUDE.md sections a page covers (the root's Architecture `###` sections and each nested `CLAUDE.md`'s `##` ones), by heading without its parenthetical (`Debug system`). `::: claude-md` (`claudeMd.ts`, no content) renders the dev-only "Read more" line linking them in the editor (nothing in `public`). The coverage check (`checkClaudeMdCoverage`, right after page discovery) makes an unknown `aek:covers` name an error, and a section that no page covers and that isn't in `hub.config.ts`'s `coverageIgnore` (the folder split, plans, bootstrap flow, this Hub section, build config notes) a warning at its line. The check reads the files through `readClaudeMdSections` (`repoFiles.ts`; the nested ones are what `git ls-files` lists, untracked ones included), is skipped where the root file isn't there (a build outside the repo), and adds them to the build's files, so in dev saving a new section warns.
  - The homepage is a generated section (`generated/home.ts`, path `''`): `generated-hero-side` (`engine_metadata.description`), `generated-whats-new` (`CHANGELOG.md`'s latest entry: date, branch, a row per part with version and codename, linked to its Version page anchor by a checked `hub:` link built from the heading's `slugify`, since the homepage renders before the changelog fills `latestChange.hash`) and `generated-quick-links` (Documentation, Examples, Issues, GitHub from `package.json`'s repository). Its featured features and examples are `::: cards … featured` slots (`featured-features.md`, `featured-examples.md`); the quick start is its own page (`examples/quick-start/`) so it can be a card.
- Issue files (`docs/issues/*.md`): `**Title:** …` on line 1, then from line 3 a block of `Key: value` lines, `Status:` first (`open`, `not filed yet`, `fixed`, …; text after a `|` is a detail shown next to the badge: `Status: open | fixed upstream on dev`), then the others that apply (`File at`, `Category`, `Found`, `Our workaround`), then a blank line and the issue itself. `fixed`, `closed`, `resolved`, `done` and `won't fix` are listed last. A file without a `**Title:**` line warns, and one without `Status:` is shown as "Status not stated".
